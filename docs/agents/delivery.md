# 交付标准与开发流程

---

## 推荐开发顺序

```
1. 修复编码/运行时错误
       ↓
2. 补齐配置一致性
       ↓
3. 修通 Streamlit → Agent → Tool → RAG 最小链路
       ↓
4. 增加文档入库脚本
       ↓
5. 增加最小测试
       ↓
6. 增加 README + .gitignore
       ↓
7. 扩展真实业务工具和多轮记忆
```

---

## 交付 Checklist

每次功能修改完成后，必须说明以下四项：

- [ ] **改了什么** —— 涉及哪些模块和文件
- [ ] **解决了什么** —— 问题描述或需求
- [ ] **如何验证** —— 运行命令、测试方法、预期结果
- [ ] **还有什么限制** —— 已知问题、未覆盖场景、技术债务

---

## 完成标准

> 未通过基本运行验证 ≠ 已完成。

在声明"完成"之前，必须：

1. 代码可运行，无 import / 语法 / 配置错误
2. 新增逻辑经过手动验证或自动化测试
3. 关键节点有日志记录
4. 符合 [硬边界规则](hard-boundaries.md)
