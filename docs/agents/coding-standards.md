# 编码规范与异常处理

---

## 代码风格

- 遵循 PEP 8
- 命名：清晰英文，名如其责。禁止 `x`、`tmp`、`data2` 等含糊名称
- 文件、函数、类名应表达职责

## 类型标注

- 新增公共函数优先补充类型标注
- 不在 import 阶段执行重型初始化（加载模型、创建向量库、批量读取文档）

## 路径处理

- 所有路径统一走 `utils.path_tool.get_abs_path` 或等价方法
- 不写死绝对路径

---

## 异常处理

### 必须

- 指定具体异常类型
- 异常发生时：记录日志 → 向上返回明确错误
- 关键路径必须有异常处理（配置加载、模型初始化、工具调用、RAG 检索、向量入库）

### 禁止

- `except:` 裸异常捕获
- 模块全局静默吞异常
- 异常堆栈直接暴露给最终用户

### 分层

| 层面 | 做法 |
|------|------|
| 用户可见 | 简洁的中文错误描述 |
| 开发日志 | 完整 traceback + 上下文 |

---

## 其他禁止事项

- `print()` 替代日志
- API Key / Token / 密码写入代码或 YAML 配置
- 用户输入拼接为 shell 命令

---

## 开发原则

| # | 原则 | 说明 |
|---|------|------|
| P1 | 链路优先 | 先跑通最小闭环，再做能力扩展 |
| P2 | 配置驱动 | 模型名、路径、检索参数、提示词路径一律走配置 |
| P3 | 职责单一 | 编排层不处理文档解析/向量入库/UI 展示 |
| P4 | 诚实语义 | 工具输出真实；Mock 标注；RAG 不足则拒答 |
| P5 | 提示词可测 | 禁止宽泛、相悖规则；每次修改可验证 |
| P6 | UTF-8 统一 | 中文内容统一 UTF-8 |
