# 模块开发规范

---

## Agent 编排 (`agent/`)

- 初始化只做：模型 + 系统提示词 + 工具 的组装
- 系统提示词传字符串，不传函数对象
- 流式输出兼容：普通消息 / 工具调用 / 异常
- 中间过程展示由 UI 或配置控制
- **禁止**：直接写向量库、直接读原始文档、处理文档解析

---

## Tool (`agent/tools/`)

### 每个 Tool 必须满足

- [ ] 名称表达力强（禁止过宽泛名称）
- [ ] `description` 用中文写清：用途、输入、输出
- [ ] 入参结构化
- [ ] 出参为稳定 string 或结构化对象
- [ ] 外部服务调用：超时 + 错误处理 + 日志
- [ ] Mock 工具在 name/description 中显式标注 `[MOCK]`

### 禁止

- 读取用户隐私文件
- 无边界访问本地文件系统
- 异常堆栈直接暴露给最终用户
- 返回与真实世界不一致的随机数据（除非明确是 Mock）

---

## RAG (`rag/`)

### 四阶段链路

```
1. 文档加载 → 2. 文档切片 → 3. 向量入库(md5去重) → 4. 检索问答
```

### 约束表

| 要点 | 约束 |
|------|------|
| md5 来源 | 原始文件内容，不允许用 Document 对象代替 |
| 空检索 | 返回明确的无上下文响应 |
| 上下文拼接 | 限制长度，避免超出模型上下文窗口 |
| metadata | 保留来源文件、页码或分片信息 |
| 向量库路径 | 必须可配置 |

### 切片参数

- 使用统一的 `chunk_size`、`chunk_overlap`、`separators`
- 配置来源：`config/chroma.yml`

## Prompt (`prompts/`)

| 文件 | 用途 | 必要变量 |
|------|------|----------|
| `main_prompt.txt` | 系统提示词 | — |
| `rag_summarize.txt` | RAG 总结模板 | `{question}` `{context}` + 拒答策略 + 来源展示 |
| `report_prompt.txt` | 报告类提示词 | — |

### 禁止

- 互相冲突的角色设定
- 要求模型编造事实、来源、时间、用户信息或工具结果
- 把工具调用协议写成自然语言幻觉规则（工具调用应由 LangChain tool schema 承担）
- 把业务密钥、内部路径、真实用户隐私写入 prompt

---

## UI (`app.py`)

### 应该做

- 问题输入框
- 流式展示回答
- 显示错误信息
- 可选显示引用来源

### 不应该做

- 硬编码模型和检索参数
- 文档切片逻辑
- 向量库底层操作
- 工具实现逻辑
- 模型初始化细节
